# Translater

macOS 文档翻译工具。打开 `.md` / `.txt`，整篇译成另一种语言，可导出纯译文。
使用系统设备端翻译模型（`Translation.framework`），不联网、不限字数、零成本。

## 使用

1. 双击 `Translater.app`
2. 主窗口选好「源语言 / 目标语言」（源语言可设自动检测）
3. 点「打开文件…」，选 `.md` 或 `.txt`
4. 文档窗口工具栏：打开 / 翻译 / 只看译文 / 导出
5. 「导出」写出 `<原名>.zh.md` 纯译文

也可以直接把文件拖到应用图标，或 `open -a Translater.app 文件.md`。

## 逐段编辑与回译

文档窗口是**逐段对照编辑器**：左边原文、右边译文，两边都能改。

| 操作 | 效果 |
|---|---|
| 改原文 | 该段标脏（浅蓝底），可重译 |
| 改译文 | 该段标脏，可回译回原文语言 |
| 工具栏「重译」 | 重译当前所在段；新旧不同会弹对比让你选 |
| 工具栏「回译改动」 | 把所有改过的译文段回译成原文语言，替换原文 |
| 锁图标 | 锁住该段，批量操作跳过它 |
| 「导出译文」 | 输出全译文文件（如 `xxx.zh.md`） |
| 「导出原文」 | 输出全原文文件（如 `xxx.src.md`），回译过的段落用回译结果 |

典型流程（英→中举例）：

1. 打开英文文档 → 工具栏「整篇翻译」
2. 逐段读中文，直接在右边改（错译、措辞、术语）
3. 改完点「回译改动」→ 改过的段落回译成英文，替换左侧原文
4. 「导出译文」拿全中文，或「导出原文」拿全英文

中→英同理，方向自动判断。「回译」得到的是**用你的中文重新表达的英文**，不是原作者原话。

## 语言包

语言包是系统资产，第三方应用不能代下载。主界面显示当前语言对状态：

- 绿点「已就绪」→ 可以直接翻
- 橙点「未下载语言包」+「下载…」→ 跳到 系统设置 → 通用 → 语言与地区 → 翻译语言 自行下载
- 红点「系统不支持」→ 该语种没有设备端模型

注意：语言包按「语言＋地区」分开，英文（美国）和英文（英国）是两份不同的包。

## 命令行

```bash
# 整篇翻译并写出文件
Translater.app/Contents/MacOS/Translater --selftest in.md out.md
```

## 实测性能

| 场景 | 结果 |
|---|---|
| 中 → 英 2 万字 | 28 秒，约 700 字/秒 |
| 英 → 中 2 万词（11.2 万字符） | 43 秒，约 2600 字符/秒 |
| 4,229 字英文 md | 2.6 秒 |
| 内存（引擎常驻） | 约 280 MB，英译中峰值 600 MB |

## 构建

```bash
./setup.sh
open Translater.app
```

`setup.sh` 会自动完成：检查工具链 → 选签名身份 → 编译 → 签名。

签名身份的选择顺序：

1. 环境变量 `SIGN_IDENTITY`
2. 已有的自签证书「Translater Local Signing」
3. 钥匙串里任意一张可用的代码签名证书
4. 都没有 → **现场生成一张自签证书**并导入登录钥匙串
5. 导入失败 → 退回 ad-hoc 临时签名

```bash
./setup.sh --ad-hoc                          # 只用临时签名，不碰钥匙串
SIGN_IDENTITY="证书名" ./setup.sh             # 指定证书
```

为什么要固定签名：ad-hoc 签名每次编译都会换哈希，系统按哈希认身份，
屏幕录制等授权会每次失效。用固定身份（开发证书或自签证书）后，重编译不会再掉权限。

## 给别人装

对方需要 macOS 26+ 和 Xcode Command Line Tools（`xcode-select --install`）。

```bash
git clone https://github.com/ygelonJIN/Translater.git
cd Translater
./setup.sh
open Translater.app
```

不需要 Apple 开发者账号：`setup.sh` 会给他生成一张属于他自己机器的自签证书，
签名后应用能正常运行，系统授权在重编译后也能保留。

## 已知限制

- 只处理纯文本类文件（`.md` / `.txt`），docx / pdf 尚未支持
- 数字、金额、专名容易翻错，后续要加占位符保护
- 半文言、古诗文翻译质量差
